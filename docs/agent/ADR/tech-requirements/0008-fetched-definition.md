# ADR tech-requirements-0008: 「取得済み」を D1 の有無で決められず、前回の取得で上位にあった 5 件の post_id に行き当たるまでめくる形で 9-13 を確定した

- **Status**: 有効
- **Date**: 2026-11-01・02
- **対象**: docs/agent/tech-requirements.md — 入力元の対応表、3 の境界値、4-1・4-2、5-3・5-7・残高切れ、7 の判定 1、8 の作業 2・3、9-13
- **出典**: issue #63（親 #57）、[ADR tech-requirements-0007](0007-x-api-entry.md)、利用者の判断（2026-11-01）、https://docs.x.com/x-api/users/get-liked-posts

## それまでの結論

[ADR tech-requirements-0007](0007-x-api-entry.md) が入口を X の API に替えたとき、「取得済み」の定義と持ち方を 9-13 の未確定として残していた。本 ADR がそれを確定に替える（0007 は取り消さない）。本文は次の形だった。

- 3 の境界値: 「取得済み（定義は 9-13）なら保存せず、Jev も呼ばない。1 時間おきに最新 5 件を取るので、新しいいいねが無い回は毎回起こる。保存して D1 から消した投稿（5-19）と、捨てた非 IT 系も、取得済みとして扱う」
- 5-3: 「最新 5 件（`max_results=5`）。5 件とも未取得なら次のページも取る」
- 9-13: D1 の有無では決められない。(a) 非 IT 系と判定失敗の投稿は D1 に書かないので毎時「未取得」に見え、Jev の再判定と次のページの取得が毎回起こる。(b) 5-19 の保存で D1 から消えた投稿が `liked_tweets` の最新 5 件に残り、判定し直されて翌日のバッチに重複する。(c) D1 が空の初回に「次のページも取る」の止まる場所が決まっていない。最後に見た最新のいいねの `post_id` を持つ形が候補だが、4-2 に列が無い

## 何が起きたか

#59 で 9-13 に残した (a)〜(c) を、Worker A の実装（8 節の作業 3）の前に決める必要があった。利用者が 2026-11-01 に止め方の骨組みを決め、pr-reviewer 1 周目（PR #64）の所見を受けて 2026-11-02 に上限と止め方を決め直した。

## 新しい結論

- 取得済みは、覚えた `post_id` に新しい順にめくって行き当たった位置以降の投稿。D1 の有無では決めない。ページ内に 1 件でも行き当たればそこで止める。覚えは `seen_likes`（最大 5 件）
- ページは最大 10（50 件）。全部に行き当たらなければ、50 件を何も扱わず `seen_likes` も変えず、`ingest_state` の止める印を立てて定期の取得を止める。再開は利用者が `wrangler d1 execute` で `halted_at`・`halt_reason`・`failing_since` を NULL にし、`seen_likes` も消す。通知は作らない。止まっていた間のいいねは取り込まない
- 初回（`seen_likes` が空）は 1 ページを覚えるだけで、取り込まない（FR-01.7）
- `seen_likes` の置き換えは、その回の投稿を全部扱い終えた後。途中で失敗した回は何も扱わなかったことにして次の回で取り直す。失敗が UTC の日付をまたいで続いたら止める印を立てる（同じ投稿は同じ UTC 日に 1 回だけ課金されるので、日をまたぐ取り直しは料金が重複する）
- 許す: 再いいねでの再取り込み、覚えている投稿を取り消して再いいねしたときに間のいいねが落ちること、止まっていた間のいいねの取りこぼし、取り直しでの非 IT 系の再判定、捨てた投稿が取り直されないこと
- 実装者の判断は、件数 5（1 ページ分をそのまま覚えられる）、ページを全部取ってから扱うこと、`posts` の書き込み・`seen_likes` の置き換え・`failing_since` の NULL 戻しを D1 の batch 1 つにして、途中で失敗した回に `posts` の行を残さないこと（残ると 18:00 をまたいだ取り直しで翌日のダイジェストに重複する）、失敗に数えるのを 1 ページ目の取得が済んだ後（課金が起きた後）に限ること。それ以外は利用者の決定
- Design Doc は入口に 9-13 を指す一言だけ足した（ADR design-doc-0004）。上流に返す△は残らない

## 影響

- 9-13 を表の確定行にし、「9-13 の確定内容」を利用者の決定と実装者の判断に分けて足した
- 4-2 に `seen_likes`（`post_id`、`position`）と `ingest_state`（`halted_at`、`halt_reason`、`failing_since`）を足した。5-8 の確定と 5-19 の削除は触らない
- 入力元の対応表は Design Doc の文に戻した。3 の境界値、4-1、5-3（検査に上限、印、初回、途中失敗、日付またぎを足した）、5-7、残高切れ、7 の判定 1（初回の取り込みを待ってからいいねする）、8 の作業 2〜4 を合わせた
- コードは変えていない。`seen_likes` と `ingest_state` の実装は #42 の配下（#60）で足す。本番 D1 への適用は人が手元で行う（ADR tech-requirements-0003）
