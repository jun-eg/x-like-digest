# ADR design-doc-0003: 入口の IFTTT Free が credit の量で崩れ、X の API で自分のいいねを取りに行く形に替えた

- **Status**: 有効
- **Date**: 2026-11-01
- **対象**: docs/agent/design-doc.md — 1 Overview / 5 Alternatives Considered / 6 スコープ内「入口」・スコープ外・前提・埋まっていないこと（△） / 7 マイルストーン 1
- **出典**: issue #58（親 #57）、X の公式料金表（https://docs.x.com/x-api/getting-started/pricing 、2026-11-01 に読んだ）、oEmbed の実機 GET（2026-11-01、下記）、利用者の判断（2026-11-01、#57・#58 と本 ADR を書く会話）

## それまでの結論

[ADR design-doc-0002](0002-ifttt-applet-works.md) が「IFTTT Free の Applet は実機で成立した。入口の構成は変えない」と確定していた。本 ADR がそれを上書きする。本文は次の形だった。

- 1: 「固定費 $0 の Cloudflare 無料枠で無人運用する。」
- 5 却下表: 「自宅サーバー・Cloudflare Containers・X API 課金 | 常時稼働や有料 API を使う | 固定費を発生させない方針に反する」
- 6 スコープ内: 「入口。X の『いいね』を IFTTT Free が検知し、公開 Webhook 1 本（Worker A）に HTTPS で送る。共有シークレットで認証し、JSON を検証する」
- 6 スコープ外: 「X API への直接課金、公式 Activity API」
- 6 前提: 「IFTTT Free のアカウントと Applet | 利用者が導入時に作る」
- 6 △: 「【確定 2026-11-01】IFTTT Free で『New liked tweet by you』から Webhook を送る Applet は、実機で成立した。（略）」「成立に伴う制約。Free はトリガーの確認が 1 時間に 1 回（略）1 回の実行は 120 credits（トリガー 100、アクション 20）で、残りの credit と補充周期は未確認」「判定 1 は、IT 系 2 件が 2 行で保存され（略）満たした」
- 7 マイルストーン 1 の完了の定義: 「IFTTT から Worker A に届き、IT 系だけが D1 に重複なく溜まる」

## 何が起きたか

0002 で未確認だった credit の残りと補充周期が分かった。IFTTT Free は 1 回の実行で 120 credits（失敗しても 100）かかり、月の無料枠では 8 件分しか流せない。利用者が 2026-11-01 に IFTTT をやめると決めた（#57）。

代替 3 案（X の API で取りに行く、スマホの共有から送る、ブラウザ拡張で拾う）を費用・いいねしてからの操作・届く確かさで比べた（#58）。利用者は「無料を優先し、無料の代替がどうしても無いときに限って月 100 円以下を許す」としたうえで、PC のブラウザで X を使わないこと、いいねは 1 日 2〜10 件であること、X Developer のカード登録とクレジットの先買いは許容することを答え、「いいねを押すだけ」を守る X の API 案を採った。

確かめた事実は 2 つ。

- X の API に無料枠は無く従量課金（2026-02-06 から）。本人の `GET /2/users/{id}/liked_tweets` は owned read で 1 件 $0.001。同じ投稿は同じ UTC 日に 1 回だけ課金（公式は soft guarantee と注記）。月額の最低額は無い。expansions で返す利用者情報は 1 件 $0.01
- X の oEmbed（`https://publish.x.com/oembed?url=...`）は無認証・制限なしで動く。9-8 に記録のある投稿 ID で GET し、200 が 0.2 秒で返り、本文・投稿者名・ユーザー名・投稿日・本文中のリンクが取れた

## 新しい結論

入口は、Worker A が X の API で自分のいいねを 1 時間おきに取りに行く形にする。1 回に取るのは最新 5 件で、5 件とも未取得なら次のページも取る。投稿者名は oEmbed で引き、expansions は使わない。いいねから D1 に届くまで最大 1 時間かかる点は IFTTT Free と同じ。

費用は変動費で、1 ドル 150 円なら月額 ≒ 23 円（UTC の日付をまたいで上位に残る前日分 5 件 × 30 日）＋ 4.5 円 × 1 日のいいね件数。1 日 2〜10 件で月 32〜68 円、17 件で 100 円の線。1 の「固定費 $0」は保ち、変動費の上限 100 円を併記する。5 の「X API 課金」の却下と 6 スコープ外の「X API への直接課金」は外し、代わりに IFTTT Free・IFTTT の有料プラン・スマホの共有・ブラウザ拡張を 5 の却下表に入れた。

0002 の実機の記録（Applet が組めたこと、判定 1 を IT 系 2 件で満たしたこと）は事実として残り、0002 と技術の要件定義 9-8 から辿れる。生きているのは「IFTTT Free でも組める」という事実だけで、入口としての結論は取り消し。

## 影響

- 1 Overview の末尾に、変動費が X の API だけで月 32〜68 円に収まる旨を足した
- 5 の却下表から「X API 課金」を外し、IFTTT Free・IFTTT の有料プラン・スマホの共有・ブラウザ拡張の 4 行を足した
- 6 スコープ内の「入口」を X の API で取りに行く形に書き換えた。スコープ外を「公式 Activity API、expansions による利用者情報の取得」に、前提の IFTTT の行を X Developer のアカウント・OAuth 2.0 のアプリ・クレジットの購入に書き換えた
- 6 の△の【確定】3 行を取り消しの 1 行に畳み、X の API の費用の見積もり・soft guarantee と料金の変動・判定 1 の測り直し、の 3 つを新しい△として置いた
- 7 のマイルストーン 1 の完了の定義を「X の API から Worker A が取り込み」に書き換えた。時期は動かしていない（測り直しの日取りは #42 の配下で決める）
- 2 と 4 は変えていない。X の API 案は、いいねを押す操作を変えないので「新しく覚える操作は無い」は真のまま
- 技術の要件定義（2 節・4-1・7 節の判定 1・8 節・9-8 ほか）と ADR tech-requirements-0006 の書き換えは #59、コードと #42 の配下の直しは #60
- 0002 の Status を「取り消し（ADR design-doc-0003 が上書き）」に書き換えた
