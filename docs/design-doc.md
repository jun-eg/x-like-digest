# Design Doc の要約: X いいね IT 情報デイリーダイジェスト

X でいいねした投稿のうち IT 系だけを集め、毎日 18:00 に Claude が A4 約 1 ページの日本語ダイジェストにして GitHub に積む。
集める操作はいいねを押すだけで変えない。Cloudflare の無料枠で固定費 0 の無人運用にする。

## 決めたこと

- 困りごとは、いいねが溜まるだけで読み返さず、興味の偏りがどこにも蓄積されないこと。根拠は利用者本人の証言のみ
- ジャーニーマップと HMW は起こさない。利用者が本人 1 人なので壁打ちで代えた
- 価値は 2 つ。帰宅後に 1 ページ読めば済むことと、偏りが日付つきで GitHub に残ること
- 入口は X のいいね。ブックマークはいいねに含まれるので取らない
- IT 系の判定は Jev。Claude は費用、キーワードは拾い漏れで却下
- 1 日 1 回 18:00、A4 約 1 ページ。即時と週次は却下
- 置き場は GitHub。Obsidian はローカルなので別の端末から開けない
- 要約は 1 回だけ。失敗したらその日の投稿は捨てる。翌日への持ち越しは話題が古くなるので却下
- GitHub 保存は翌日 18:00 の本処理まで再試行する。cron は 10 分おき 1 本、次に試す時刻はジョブが持つ。1 時間で打ち切る当初案は、無料枠が再試行を縛らないので却下
- Worker を 3 本に分けて権限を分離する。プロンプトインジェクションの事前検査はしない
- MVP は要件定義書の P1〜P5 全部。無人運用には再試行と冪等性が要る
- スコープ外は、いいね台帳、ダイジェストを開発環境へ取り込む自動化、原文の永続保存、通知、承認フロー、複数利用者
- 時期は 5 段とも 2026-11-01。2026-11-08 に 1 週間運用の見直しを置く

## 開いていること

- IFTTT Free で X のいいねから Webhook を送る Applet が実機で成立するか。成立しなければ入口の構成が変わる
- Jev の閾値や CPU 10 ms などの値は、判断は済んでいるので技術の要件定義に送る
