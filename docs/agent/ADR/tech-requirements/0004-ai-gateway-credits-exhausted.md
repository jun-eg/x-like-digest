# ADR tech-requirements-0004: AI Gateway の残高切れ（2021）を 5-6 の「判定失敗は捨てる」に含め、通知は作らないと決めた

- **Status**: 有効
- **Date**: 2026-11-01
- **対象**: docs/agent/tech-requirements.md — 3 節「境界値と特別扱い」、5 節 6 行目と「残高切れの扱い」
- **出典**: issue #34、PR #30（#16）の pr-reviewer 所見、ADR tech-requirements-0002、人の決定（2026-11-01）

## それまでの結論

5-6 は「Jev の時間切れ・例外・形式不正で D1 に書かず 2xx を返す。再送を求めない」。残高切れ（前払いクレジットが尽きた）が例外に入るかは書いてなく、気づく手も決めていなかった。

## 何が起きたか

#16 の実機確認で、Top-up 前の AI Gateway が `AiGatewayError: 2021: Insufficient AI Gateway credits` を返した。残高が尽きれば、その間のいいねは誰にも知らされずに捨てられる。PR #30 の pr-reviewer が、依頼の範囲外として人の判断に回した。

## 新しい結論

- 残高切れは 5-6 の例外に含める。D1 に書かず 2xx を返し、再送を求めない。要件定義書 FR-03.5 は変えない。専用の分岐は持たない
- 気づく手は新しく作らない。その日のダイジェストが届かないことで、利用者本人が気づく
- 限界を書いた。(a) 日の途中で尽きると、尽きる前の投稿でダイジェストができ、捨てた件数は分からない。(b) いいね 0 件の日もダイジェストは作られず、残高切れと見分けがつかない
- 却下した案（保留して再判定、`2021` だけ 5xx、Cloudflare 側の通知、メール、GitHub への別ファイル・注記・issue）と理由は、技術の要件定義の 5 節「残高切れの扱い」に書いた

## 影響

- 3 節の境界値に 1 行、5-6 に「`2021` を含む」と検査の手、5 節に「残高切れの扱い」を足した
- 実装への影響は、Worker A の Jev 呼び出しの例外を種類で分けないこと。検査に `2021` の `AiGatewayError` を足す
- 既存の決定は覆していない。5-6 の読み方を明示した
